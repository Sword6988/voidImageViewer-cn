void Image Viewer 汉化包方案

「单文件替换」式本地化补丁 · 设计与实测说明  |  2026-09-21

一句话结论：本程序可用的「单文件替换」落点只有一个 —— 安装目录里的 主程序 voidImageViewer.exe 本身。外挂 DLL、代理 DLL、语言文件这三条更省事的路， 经实测全部不可行（下文给出注册表与对照实验证据）。因此方案定为： 交付一个体积不变、只需覆盖同名 exe 的汉化版二进制，并配套一个 「版本自适应重建器」解决升级后的重新生成问题。

0. 先排除掉走不通的路（实测证据）

「替换单个文件即完成汉化」最自然的实现是外挂一个 DLL。但这条路在本程序上被三层机制封死，逐条实测如下。

候选路径结论实测依据

由此确定：唯一满足「只替换一个文件」且不动注册表的落点，就是主程序 exe 本身。

1. 汉化文件的生成方式

生成物是一个 x64 原生 PE 二进制：在保留原版全部代码与资源的前提下，追加一个 新的可执行节 .cnstr 存放 UTF-8 中文，并把原本指向英文的引用改指向新节。 整体分五步，全部由 rebuild_cn.py 自动完成。

1.1 核心：把「硬编码地址」换成「内容签名」

旧构建器把 145 个绝对指针、54 处 LEA、5 处循环的地址全部写死在数据文件里， 程序一升级就全部失效。新方案改为按内容/形状现场定位：

定位项定位手段为什么跨版本稳定
待翻译字符串 扫描 .rdata / .data 的 NUL 结尾 ASCII 串与 UTF-16 串， 建「文本 → 地址」索引，再用翻译表的原文去查 翻译表本身就是以原文为键的字典，与地址无关。文本不重写就永远能命中； 同一句话出现多处时会全部命中并全部替换。
绝对指针引用 全映像顺序扫描 8 字节值，命中 ImageBase + 目标RVA 即记录 程序 DYNAMIC_BASE 未开启、无重定位表，映像恒载于 0x140000000， 绝对指针是字面量，扫描可靠。
RIP 相对 LEA 手工解码 REX? 8D /modrm(mod=00,rm=101)/ disp32，回算 addr+size+disp 是否等于目标 RVA 不依赖任何反汇编库；同一条指令会被 REX 前缀与 0x8D 各命中一次， 按位移字节的文件偏移去重，并在写入前回读校验。
5 处拓宽循环
（乱码根因）		 搜索 45 字节代码模板 实测 5 处逐字节完全相同，且尾部必须紧跟「写 0 结尾」指令，双重条件唯一确定。
UTF-8 转换函数 搜索 33 字节模板（含 mov ecx, 0FDE9h 即 CP_UTF8）；未命中则退化用锚点 + 邻近 call qword [rip+x] 推断 两级匹配，模板失效时仍有兜底；定位后还会断言它没有被 LEA 补丁命中。
新节 RVA 取最后一段节区的 VA + align(VSIZE) 再按节对齐上取整 不再写死 0x60000，节区数量或大小变化都能自适应。

1.2 关键一步：修掉「逐字节 1:1 拓宽」

程序内部有 5 处内联循环，把 ANSI 字节直接当宽字符写入列表控件 —— 这在纯 ASCII 下没问题， 换成 UTF-8 中文必然乱码。生成器把这 5 处循环的开头改写成一次 call，跳到新节里的 代码洞 cave_strip_widen（90 字节）：

; 代码洞：入参 rcx=源(ANSI) rdx=目标(wchar)，返回时 rdx 指向译文末尾
push r8 / push r9 / sub rsp,0x38
mov [rsp+0x20], rdx      ; 保存目标指针
xchg rcx, rdx            ; rcx=目标, rdx=源
call MultiByteToWideChar(CP_UTF8)   ; ← 复用程序自己的转换包装
mov rdx,[rsp+0x20] / mov rcx,rdx
WLOOP:  ; 按助记符规则剥离 '&'：'&&'→'&'，单 '&' 丢弃
        …  ; 其余字符原样照抄
WDONE:  add rsp,0x38 / pop r9 / pop r8 / ret

2. 需要替换的目标文件及其位置

项目内容
目标文件C:\Program Files\voidImageViewer\voidImageViewer.exe
操作同名、同目录覆盖。文件名必须保持 voidImageViewer.exe
安装目录现有文件 Uninstall.exe（卸载器，不要动）
voidImageViewer.exe（主程序，被替换的就是它）

为什么不能改名程序用自身路径定位配置与安装选项；Uninstall.exe 与开始菜单快捷方式也按该文件名引用。 改名会导致配置失效与卸载异常。
两种替换方式（任选其一）
  1. 一键（推荐）：双击汉化包里的 汉化.bat —— 自动备份原版 → 生成 → 覆盖 → 启动自检。
  2. 纯手动：先跑一次 仅生成.bat 得到 cn_out\voidImageViewer.cn.exe，再把它复制到安装目录并改名为 voidImageViewer.exe 覆盖（建议先自行备份原版）。

3. 替换后生效的条件

本程序对自身文件不做完整性校验，这是方案成立的前提。实测已确认：

  • 无自校验逻辑：改动后的 exe 可正常启动、菜单与对话框全部为中文；
  • PE 校验和已由生成器重算，SizeOfImage / 节区数 / 资源目录大小 / 证书目录偏移均已同步更新；
  • Windows 对本地文件替换不做 Authenticode 强制校验（仅对「来自网络的下载文件」附加 Mark-of-the-Web 时才有 SmartScreen 提示）。

因此生效点为：进程启动时加载 exe → 静态读取新节的译文与重建后的资源。不需要重启系统、不需要改注册表、不需要任何运行时注入。

三个前提条件（缺一不生效）
  1. 被替换的必须是原版。若目标已含 .cnstr 节（说明已是汉化版），生成器会自动改用 备份\ 里的原版重建；若备份也不存在，会明确报错要求先用安装包的原版覆盖。
  2. 覆盖时程序不能正在运行，否则文件被占用，写入会失败。
  3. 写入 C:\Program Files 需要管理员权限。报权限错误时右键 汉化.bat → 「以管理员身份运行」。

如何确认已生效：生成器带 --verify，会启动程序、枚举主窗口、用 GetMenuStringW 读回菜单文本，只要检测到中文字符即输出 自检结论：菜单已为中文 ✅。手动核对可打开「关于」对话框或 「选项 → 控件」页，后者能一并验证列表乱码修复。

4. 程序更新导致结构变化时的兼容性处理

4.1 不同变化类型下的表现

新版本的变化本方案表现说明 / 应对
仅字符串增删改
（地址整体平移）		无感通过 内容签名定位天然免疫地址平移。这是版本升级最常见的形态。
节区数量 / 大小变化无感通过 新节 RVA 由最后一节自动推算，不再写死 0x60000。
代码重排
（函数搬家）		无感通过 引用索引与代码模板都是现场扫描，不依赖函数地址。
新增界面文本需补词条 不会报错，但新英文会原样保留。生成器会打印未命中清单， 按原文补进 translations.py 即可，无需改其它代码。
改动那 5 处循环 / 转换函数降级 转换函数有「锚点推断」兜底；若连锚点都找不到，生成器明确报错退出， 不产出半成品，并提示检查 SIG_MBTWC。此时需人工核对后更新模板字节。
取消清单里的 SxS 依赖
或换用完全不同的框架		需重做 属结构性重写，超出本包范围。

4.2 三道自校验，保证「宁可报错，不产坏件」

  • LEA 回读校验：写入新位移前，先用旧位移回算 addr + size + old_disp 是否等于目标 RVA； 不等则跳过该处并打印告警（本次实测 0 失败）。
  • 循环尾部校验：45 字节模板之后必须紧跟写 0 结尾的指令，否则该处被剔除。
  • 交叉污染校验：断言 UTF-8 转换函数与循环区没有被 LEA 补丁命中，防止把钩子本身改坏。

4.3 升级后的标准动作（三步）

1) 正常下载安装新版本 voidImageViewer（exe 被覆盖成新的英文版）
2) 双击汉化包目录里的  汉化.bat
3) 看到「自检结论：菜单已为中文 ✅」—— 完成。
   （若打印了「未命中」清单，把新出现的英文按原文补进 translations.py 再跑一次即可）
幂等性已实测：对已经是汉化版的 exe 再跑一次 汉化.bat，程序会自动识别 .cnstr 节、改用 备份\ 中的原版重建，不会「二次打补丁」导致文件损坏。 还原.bat 也能把 exe 还原到与原始文件 MD5 完全一致（已实测： 2c30134266aabd607e186e5252f1452f）。

5. 注意事项

事项说明
数字签名失效 原版尾部 10,408 字节的 Authenticode 签名被原样搬移到新文件末尾，但文件内容已变， 签名不再有效。这不影响运行，只是「属性 → 数字签名」页会显示无效。
杀软 / EDR 告警 改动后的 exe 无有效签名，且「新增可执行节 + 修改代码」是启发式引擎的敏感特征，可能被误报。 可加白名单，或改用「仅生成 + 手动替换」降低自动化痕迹。
权限 写入 C:\Program Files 需管理员权限。生成器本身只读目标、写自己的输出目录时不需要提权； 仅在 --deploy 覆盖阶段需要。
配置文件副作用 程序把快捷键等设置写入 %APPDATA%\voidImageViewer\voidImageViewer.ini， 键名由命令名派生。汉化后少数组会出现同名，但实测快捷键取值完全一致、无设置丢失。 建议在替换前备份该 ini。
回滚 双击 还原.bat 即可从 备份\ 还原。备份文件按时间戳命名，保留多次历史， 切勿删除该目录。
不要汉化
Uninstall.exe		 卸载器体积小、按钮文案有限，改动它收益极低，且会破坏卸载时的数字签名校验路径， 更重要的是卸载时它会删除整个安装目录，改动无意义。
个别词条未落地 文件类型项 *.* (All Files)（原映像 RVA 0x44819）在原程序中 没有任何引用，且中文译文比原文长（19 > 16 字节）无法就地替换，因此跳过。 生成器会明确打印这条「[跳过·无引用且超长]」，属预期行为。
运行环境 重建器只用 Python 标准库（无需 pip 安装任何包），要求 Python 3.8+。 未装 Python 时，把 python.exe 放进包的 runtime\ 子目录即可。
